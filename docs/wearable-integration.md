# HOS 穿戴设备主动教练接入

核查日期：2026-10-25。状态：判断引擎已实现；设备接入未完成，线上网页尚未读取手环或眼镜数据。商业配置仍暂缓。

## 实际目标

由手机伴侣应用获取用户授权的真实设备数据，在手机上进行判断和提醒，写入干预回执，再由 HOS 复盘使用。GitHub Pages 继续承载原有阅读、训练、日志和复盘。不能把定时弹窗、CSV 导入或合成测试数据称为穿戴设备接入。

第一条闭环仅针对办公时段活动偏低：连续步数证据 → 建议走动两分钟 → 完成/稍后/忽略 → 用户自评是否有帮助。步数不能识别坐姿，心率不能直接识别情绪。本轮新增独立的本机相机观察试用模块（#/perception），具备真实浏览器模型推理与相对姿态校准；准确性仍需实际机位验证。

## 核实的官方路径

- [荣耀官方 Health Kit 示例](https://github.com/HONORDevelopers/HealthKit-demo)：Android SDK 支持实时心率、实时步数及组合订阅，依赖荣耀账号授权与运动健康应用。必须先实现账号授权；示例本身不会替我们创建应用身份。
- [荣耀实时数据指南](https://developer.honor.com/cn/docs/11005/guides/code-guide/android/realtimedata)：RealTimeDataClient 注册/注销监听。SDK 接入还需要已开通权限的应用身份。用户截图已确认荣耀手环 9（18.0.0.244）与 Magic8 Pro（MagicOS 11 / Android 17），健康应用版本尚待确认。
- [荣耀权限范围](https://developer.honor.com/cn/docs/11005/guides/scope)：实时读取与 Web 历史读取能力不同。不能用云端旧数据冒充实时数据。
- [小米跨设备相机官方说明](https://hyperos.mi.com/continuity/abilities/ab0007)：兼容手机可在支持的视频通话/直播场景切换眼镜相机。这不是 HOS 可以随时后台读取眼镜画面或 IMU 的公开接口。
- [小米眼镜官方应用](https://app.mi.com/details?id=com.xiaomi.superhexa)：需确认实际眼镜型号及手机。此轮未找到可验证的第三方公开相机/姿态 SDK，不逆向私有协议，不承诺已打通。

## 当前实现

`src/engines/wearableIntervention.ts` 是与平台无关的纯判断层，尚未接到生产数据入口。适配器必须独立验证授权和传输来源；通过字段校验不等于证明设备真实性。

- 每条样本带设备、连接会话、来源、采样时间、实时/历史分类及有效性。
- 未授权、断开、等待数据、数据过期明确区分。
- 默认不开启主动干预；仅在用户确认且未过期的办公情境中启用。
- 45 分钟完整窗口、最多 5 分钟采样间隔、最新数据不超过 2 分钟。缺测、计数回退、重连、冲突重放不推断为静止。
- 运动、驾驶、睡眠、专注、免打扰、暂停、冷却期均可阻止提醒。默认每小时最多一次，每天最多三次。
- 每次提醒保留依据样本及完成/稍后/忽略回执；规则不做疾病诊断或心理标签。
- 当前测试全部为合成固定样本，不等于真机验收。没有测试数据写入用户日志。

## 下一步实施门槛与验收

1. 已确认荣耀手环 9 与 Magic8 Pro；下一步确认荣耀开发者认证与 Health Kit 权限。小米眼镜和书房云台 2K 的具体型号、公开接口仍待核实。
2. 对兼容 Android 建立独立 HOS 手机伴侣应用，包名/签名固定，使用官方账号授权与 Health Kit；厂商应用创建、权限审核和用户登录均需真实完成。
3. 在手机上完成连续数据订阅、注销、撤销授权、断线重连与锁屏运行验证。常驻运行需遵循系统前台服务及电池管理规则，不能承诺所有手机永不断线。
4. 先验证系统通知和手机语音播报，再在配对眼镜上实测是否可听到、后台是否可用；未验证前不标注眼镜联通。摄像头或 IMU 需要另行获得官方接口。
5. 在手机本机保存原始证据与干预回执，用户选择后同步至受保护档案。不得向公开 GitHub 仓库写入健康数据、设备令牌或厂商密钥。
6. 验收证据必须包括真实样本时间、来源设备、到达延迟、锁屏提醒、免打扰、撤销后停止、重复通知抑制、执行反馈及复盘归档。

完成以上闭环前，线上仍应称为“成长复盘个人版”，不能称为已上线穿戴设备实时教练。
